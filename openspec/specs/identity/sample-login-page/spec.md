# identity/sample-login-page Specification

## Purpose

约束示例前端登录页对外可见的行为：以纯静态资源形式提供、同源承载会话、按后端返回的条数渲染登录入口，并遵守与后端 JSON 契约之间几条容易踩错的格式约束。

## Requirements

### Requirement: 登录页以纯静态资源提供且不依赖服务端渲染

示例登录页 SHALL 由静态文件构成，由应用直接对外提供，MUST NOT 引入模板引擎或在服务端拼装 HTML。未认证用户访问页面地址 SHALL 得到页面内容而非认证错误，且该可访问性 MUST NOT 依赖对应用安全放行规则的修改。

#### Scenario: 未登录直接访问页面

- **WHEN** 未经认证的浏览器请求页面地址
- **THEN** 返回可渲染的 HTML 页面
- **AND** 不返回需要登录的错误响应

#### Scenario: 页面资源随应用一并部署

- **WHEN** 应用以默认方式启动
- **THEN** 页面及其脚本与样式均可从同一应用地址直接访问，无需独立的静态资源服务或额外的前端构建步骤

### Requirement: 单点登录入口数量与后端配置一致

页面 SHALL 依据登录方式发现接口的返回条数渲染单点登录入口，MUST NOT 在页面代码中硬编码身份源的数量、标识或地址。

#### Scenario: 两条身份源

- **WHEN** 接口返回两条单点登录入口
- **THEN** 页面出现两个对应按钮，按钮文案为接口返回的展示名

#### Scenario: 后端追加身份源后重新加载

- **WHEN** 后端配置追加第三条身份源，页面重新加载
- **THEN** 页面出现三个单点登录按钮
- **AND** 页面代码未做任何修改

#### Scenario: 接口返回空身份源列表

- **WHEN** 接口返回的单点登录列表为空
- **THEN** 页面不出现任何单点登录按钮，账号密码表单仍可用

### Requirement: 业务请求由脚本发起并只以响应体判断结果

页面 SHALL 以脚本方式发起登录方式查询、账号密码登录与登录态查询，并 MUST 以响应体中的业务成功标记作为结果判据，MUST NOT 仅依据 HTTP 状态码判断成败。

#### Scenario: 凭据错误

- **WHEN** 用户提交错误密码，后端返回表示失败的状态码与业务失败标记
- **THEN** 页面在表单区域显示失败提示
- **AND** 页面不发生跳转

#### Scenario: 状态码与业务码不一致的失败

- **WHEN** 后端以表示成功的 HTTP 状态码携带表示失败的业务码返回
- **THEN** 页面判定为失败并提示，不进入已登录视图

### Requirement: 账号密码请求的媒体类型精确匹配

页面 SHALL 以不含任何参数的 JSON 媒体类型声明提交账号密码请求。该约束是后端解析逻辑的已知敏感性所致：附带字符集参数的同类型声明会使请求被按表单解析从而认证失败。

#### Scenario: 提交账号密码

- **WHEN** 页面发起账号密码登录请求
- **THEN** 请求头的媒体类型值恰为 JSON 类型且不含参数
- **AND** 请求体只包含接口返回的用户名字段名与密码字段名

### Requirement: 单点登录经由顶层浏览器导航发起

页面 SHALL 通过顶层浏览器导航发起单点登录流程，MUST NOT 以脚本请求方式发起该流程起点。页面 SHALL 在因单点登录被重定向回页面后，依据地址中的状态标记与登录态查询结果呈现已登录视图。

#### Scenario: 单点登录完整往返

- **WHEN** 用户点击单点登录按钮并在身份源完成认证
- **THEN** 浏览器经历身份源往返后回到页面地址
- **AND** 页面呈现已登录状态，用户在整个过程中未看到裸 JSON 文本

#### Scenario: 回跳地址被保留在历史记录

- **WHEN** 页面因单点登录回跳而加载并读取到状态标记
- **THEN** 页面清除地址中的状态标记，使其不残留于地址栏显示

### Requirement: 访问应用根路径进入首页并在未登录时转入登录页

应用根路径 SHALL 返回首页页面而非认证错误。用户未认证时，首页 SHALL 转入登录页；已认证时 SHALL 停留首页并显示当前用户。该转入由首页自身的脚本完成，MUST NOT 依赖后端为根路径返回重定向。

#### Scenario: 未登录访问根路径

- **WHEN** 未经认证的浏览器访问应用根地址
- **THEN** 得到可渲染的首页，随后自动进入登录页并展示登录表单
- **AND** 屏幕上不出现"权限不足"之类的 JSON 错误内容

#### Scenario: 已登录访问根路径

- **WHEN** 已认证的浏览器访问应用根地址
- **THEN** 停留在首页并显示当前登录名与权限

#### Scenario: 从首页登出

- **WHEN** 用户在首页点击登出
- **THEN** 回到登录页，且再次访问根地址仍会转入登录页

#### Scenario: 登录页提供进入首页的入口

- **WHEN** 用户在登录页完成任一方式登录
- **THEN** 登录页呈现可点击的首页入口

### Requirement: 登录态在页面重新加载后可恢复

页面 SHALL 在每次加载时判定当前会话是否已认证，并渲染与之匹配的视图；MUST NOT 把登录成功响应内容本身作为登录态的唯一来源。

#### Scenario: 登录成功后刷新页面

- **WHEN** 用户完成任一方式登录后刷新页面
- **THEN** 页面通过登录态查询识别为已登录并显示当前用户与登出入口

#### Scenario: 登出后

- **WHEN** 用户点击登出并成功
- **THEN** 页面回到登录表单视图，且刷新后仍为登录表单视图
