# identity/login-outcome-posture Specification

## Purpose

约束认证结果（成功与失败）以何种姿态交付调用方：由前端脚本发起的账号密码认证返回结构化数据，由浏览器整页承载的单点登录则把用户送回前端页面，两者的判别依据必须来自认证协议本身。

## Requirements

### Requirement: 认证结果交付姿态按协议类别分流

系统 SHALL 依据认证结果所属协议类别决定其交付姿态：账号密码认证 SHALL 返回结构化 JSON 响应体；OAuth2、OIDC 与 SAML2 单点登录在已配置登录完成回跳目标时 SHALL 以重定向结束流程，且该重定向响应体 MUST NOT 携带业务数据。

#### Scenario: 账号密码登录成功

- **WHEN** 前端脚本以正确的账号密码完成认证
- **THEN** 响应为 HTTP 200 与 JSON 响应体，包含用户信息与会话标识
- **AND** 响应不携带任何重定向状态码或 Location 头

#### Scenario: 单点登录成功且已配置回跳目标

- **WHEN** 用户在身份源完成认证、回调请求到达并完成协议校验
- **THEN** 响应为重定向到配置的回跳目标
- **AND** 响应体为空，不含用户信息或会话标识

#### Scenario: 单点登录成功但未配置回跳目标

- **WHEN** 应用未配置登录完成回跳目标
- **THEN** 单点登录以与账号密码相同的 JSON 响应体结束
- **AND** 本次变更前已依赖该行为的调用方观测到的响应不变

### Requirement: 交付姿态按应用整体决定而非按协议条目

回跳目标是应用整体的配置。系统 SHALL 以"该认证结果的协议类别是否属于单点登录"决定是否重定向，MUST NOT 依据该条目所属的具体协议或单条注册项做差异化决定；同一应用内的 OAuth2、OIDC 与 SAML2 结果 SHALL 使用同一个回跳目标。

#### Scenario: 混合协议配置共用一个目标

- **WHEN** 应用同时配置了 OAuth2、OIDC 与 SAML2 的身份源并设置了单一回跳目标
- **THEN** 三种协议登录成功后的重定向目标相同
- **AND** 不存在某一协议被静默留在 JSON 行为上的情况

#### Scenario: 未配置目标时三种协议一致回退

- **WHEN** 应用未配置回跳目标
- **THEN** 三种单点登录协议全部以 JSON 结束，行为彼此一致

### Requirement: 回跳目标不得携带凭证

单点登录的重定向目标 SHALL 只携带表明流程结束的状态标记。URL 的 query 与片段部分 MUST NOT 包含会话标识、访问令牌或用户信息；调用方判断登录是否成立 MUST 依赖会话自身经由 Cookie 生效，而非依赖 URL 内容。

#### Scenario: 检查回跳地址内容

- **WHEN** 单点登录成功产生重定向
- **THEN** Location 值不含会话标识与令牌
- **AND** 浏览器随后以同一会话发起的脚本请求可被认证为已登录

### Requirement: 认证失败采用与成功一致的判别依据

系统在认证过程失败时 SHALL 使用与成功路径相同的协议类别判别依据决定交付姿态。单点登录失败 MUST NOT 将结构化错误直接渲染在浏览器页面上。账号密码认证失败 SHALL 继续以 JSON 失败信封交付，并按统一错误分类规则给出认证类错误。

#### Scenario: 用户在身份源侧放弃登录

- **WHEN** 单点登录流程在身份源侧被取消，或回调的关联校验（state、InResponseTo、Audience）未通过
- **THEN** 浏览器被重定向回前端页面并携带失败标记
- **AND** 用户屏幕上不出现裸 JSON 文本

#### Scenario: 账号密码认证失败保持既有契约

- **WHEN** 账号密码认证因凭据错误失败
- **THEN** 响应仍以 JSON 失败信封结束，不发生重定向
- **AND** 状态码、错误码与提示按统一错误分类规则给出，不因姿态分流逻辑改变交付方式

### Requirement: 判别依据来自认证端点而非请求特征

系统 SHALL 以该请求命中的认证处理端点所属协议类别作为分流依据，且成功与失败使用同一依据；MUST NOT 依据 User-Agent、Accept、Sec-Fetch-* 等由浏览器行为决定的请求特征。

#### Scenario: 以表单方式而非脚本提交账号密码

- **WHEN** 账号密码请求由浏览器表单导航发出，其请求头呈现为整页跳转特征
- **THEN** 响应仍为 JSON，因为该请求命中的是账号密码处理端点

#### Scenario: 认证失败时判定依据同样可得

- **WHEN** 认证过程失败，处理处只拿得到异常对象而拿不到认证结果对象
- **THEN** 交付姿态的判定仍能完成，不因缺失认证结果对象而退回默认分支

### Requirement: 登出交付姿态不受影响

系统 SHALL 在登出时继续返回 JSON 响应体，MUST NOT 因单点登录回跳配置的引入而对登出产生重定向。

#### Scenario: 已登录会话发起登出

- **WHEN** 已认证会话以脚本方式发起登出请求
- **THEN** 响应为 HTTP 200 与 JSON 响应体，数据部分为空
- **AND** 响应不含 Location 头
