# auth/data-range Specification

## Purpose

约束数据范围查询权限：声明单位是一条查询语句而非一个调用，权限条件只作用于显式声明的语句，且声明本身写错时必须在启动阶段暴露而不是在执行时静默放开过滤。

## Requirements

### Requirement: 数据范围权限以查询语句为声明单位

系统 SHALL 把数据范围权限的声明单位定为 MyBatis 的 Mapper 接口方法：声明标在哪个方法上，权限条件就只注入该方法对应的那一条语句。系统 MUST NOT 让一次声明影响同一调用链上的其他语句。

#### Scenario: 被声明的语句被注入

- **WHEN** 调用一个声明了数据范围的 Mapper 方法
- **THEN** 该方法的 SQL 在执行前被追加权限过滤条件
- **AND** 返回结果只包含当前登录人在该权限槽位下可见的数据行

#### Scenario: 同一调用链上的其他语句不受影响

- **WHEN** 一次请求在执行被声明的查询之外还执行了其他 Mapper 方法（例如字典表、用户表的查询）
- **THEN** 未被声明的语句按业务原样执行
- **AND** 其 SQL 不被追加任何权限条件

#### Scenario: 嵌套声明不互相覆盖

- **WHEN** 一个被声明的查询在执行期间触发了另一个被声明的查询
- **THEN** 两条语句各按自己方法上的声明注入权限条件
- **AND** 外层查询不会因为内层查询结束而失去过滤

### Requirement: 数据范围过滤是显式选择的结果

系统 MUST 只对显式声明了数据范围的语句施加过滤。未声明的语句一律按业务原样执行，系统 MUST NOT 因其未声明而告警或使其失败。

#### Scenario: 未声明即不过滤

- **WHEN** 执行一个没有声明数据范围的 Mapper 方法，且该表在权限数据中存在受控记录
- **THEN** SQL 不被改写
- **AND** 返回所有满足业务条件的行

### Requirement: 一条语句绑定一个权限槽位

系统 SHALL 让每个声明点固定绑定一组业务功能标识与操作类型。同一张表需要按不同操作过滤时，MUST 通过各自的 Mapper 方法分别声明，MUST NOT 在同一次执行中改变某条语句已绑定的槽位。

#### Scenario: 同表两种操作各自过滤

- **WHEN** 同一张业务表分别存在"可编辑列表"与"可审批列表"两个 Mapper 方法，各绑定不同的操作类型
- **THEN** 两个方法返回的行集分别由各自操作类型下的权限数据决定
- **AND** 二者互不影响

#### Scenario: 同一请求内先后使用两个槽位

- **WHEN** 同一请求先调用"可编辑列表"再调用"可审批列表"
- **THEN** 第二次调用的结果不受第一次调用所用操作类型的影响

### Requirement: 只对查询语句生效

系统 MUST NOT 对 INSERT、UPDATE、DELETE 语句注入数据范围条件。

#### Scenario: 写语句不被改写

- **WHEN** 执行插入、更新或删除语句
- **THEN** 其 SQL 不被追加权限条件

### Requirement: 声明错误在启动阶段暴露

系统 SHALL 在应用启动阶段校验全部数据范围声明，并在下列任一情况使应用启动失败：声明所在方法解析不到映射语句；解析到的语句不是查询语句；该语句启用了二级缓存。

#### Scenario: 解析不到映射语句

- **WHEN** 数据范围声明标在一个解析不出映射语句的方法上（例如接口或方法名与映射文件中的 id 不一致）
- **THEN** 应用启动失败
- **AND** 失败信息指出该声明所在位置

#### Scenario: 声明标在非查询方法上

- **WHEN** 数据范围声明所在的方法对应一条 INSERT、UPDATE 或 DELETE 语句
- **THEN** 应用启动失败并指明该语句

#### Scenario: 声明所在语句启用了二级缓存

- **WHEN** 被声明数据范围的映射语句挂有二级缓存
- **THEN** 应用启动失败
- **AND** 失败信息说明数据范围过滤与二级缓存不能共存

### Requirement: 无法静态取得 SQL 的语句把表校验延后到执行期

对能够静态取得 SQL 文本的语句，系统 SHALL 在启动阶段校验声明中指定的目标表确实出现在该语句中，不匹配则启动失败。对无法静态取得 SQL 文本的语句，系统 MUST 跳过这项启动校验，并 MUST 在执行期因匹配不到目标表而抛出异常，而不是返回未经过滤的结果。

#### Scenario: 静态语句的目标表写错

- **WHEN** 一个可静态取得 SQL 的语句声明了该语句中不存在的目标表
- **THEN** 应用启动失败并指明语句与表名

#### Scenario: 动态语句只在执行期判定

- **WHEN** 被声明的语句只能通过运行期拼出最终 SQL
- **THEN** 启动阶段不校验其目标表
- **AND** 执行期若拼不出目标表则抛出异常，不返回未经过滤的结果

### Requirement: 多表语句中的目标表定位

系统 SHALL 允许声明指定权限条件挂到哪张表（表名，可选表别名）；未指定表名时挂到该语句的主表。该默认行为 MUST 只作用于本条语句。

#### Scenario: 未指定表名时命中主表

- **WHEN** 声明未指定目标表，且被声明的语句只有一张主表
- **THEN** 权限条件挂到该主表

#### Scenario: 指定表名与别名时命中关联表

- **WHEN** 声明指定了表名与表别名，且被声明的语句中该表以这一别名参与关联
- **THEN** 权限条件挂到该关联表实例，不挂到主表

### Requirement: 权限集合为空时按看不到任何数据处理

系统 SHALL 在当前登录人的权限集合为空时，让被声明数据范围的查询语句正常执行并返回零行。系统 MUST NOT 因权限集合为空而生成语法上不成立的语句，也 MUST NOT 因权限集合为空而省略过滤条件、返回未经过滤的结果。

#### Scenario: 无权限用户查询受管辖的列表

- **WHEN** 一个不持有任何权限的调用方执行被声明了数据范围的查询
- **THEN** 语句正常执行，结果集为空
- **AND** 不抛数据库语法错误

#### Scenario: 空权限不放开过滤

- **WHEN** 同上，检查该语句实际执行的过滤范围
- **THEN** 该语句仍带着权限过滤条件，只是该条件恒不成立
- **AND** 不会因为权限集合为空而退化为无条件查询

#### Scenario: 空权限只影响被声明的语句

- **WHEN** 同一次调用还执行了未被声明数据范围的语句
- **THEN** 未被声明的语句按其业务条件正常返回数据
