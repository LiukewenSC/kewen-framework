# Spec Delta

## MODIFIED Requirements

### Requirement: 权限拒绝与配置错误区分表达

系统 SHALL 区分"当前登录人无权执行该操作"与"该调用无法被判定（配置或用法错误）"两类失败，并且 MUST NOT 把框架内部类型信息作为拒绝原因输出给调用方。两类失败在对外响应中 MUST 携带彼此可区分的语义编码，使调用方不需要解析消息文本就能判出属于哪一类；该编码由框架随自动装配交付，使用方无需额外配置即可拿到。

#### Scenario: 权限拒绝输出统一语义

- **WHEN** 判定因权限未命中而拒绝
- **THEN** 返回统一的权限拒绝结果
- **AND** 未命中的 ID 明细只进入服务端日志

#### Scenario: 配置错误不被当作权限拒绝

- **WHEN** 判定因找不到承载对象、ID 集合为空或超出上限而无法进行
- **THEN** 以配置/用法类错误失败
- **AND** 对外信息不包含框架内部类名或接口名

#### Scenario: 两类失败在响应上可区分

- **WHEN** 同一次部署里分别触发权限未命中的拒绝与实参缺少业务数据ID的用法错误
- **THEN** 两个响应的语义编码彼此不同，且各自在所有权限拒绝用例 / 所有用法错误用例上保持一致
- **AND** 权限拒绝的编码不被用法错误复用，反之亦然
