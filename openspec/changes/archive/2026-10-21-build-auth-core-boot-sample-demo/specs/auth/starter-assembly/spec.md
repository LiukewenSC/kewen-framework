# Spec Delta

## Purpose

约束 auth-core 自动装配层对外交付的东西：拒绝响应通道是否随 starter 生效、出口是否唯一，以及强制/可选扩展点缺失时应用的启动结果。

## ADDED Requirements

### Requirement: 拒绝响应通道随 starter 生效

系统 SHALL 在使用方只引入 starter、不额外声明任何异常处理的情况下，把权限框架抛出的拒绝转成对外统一的响应结果。该通道 MUST NOT 依赖使用方手工扫描框架包或手工注册。

#### Scenario: 零额外配置时菜单拒绝得到统一结果

- **WHEN** 一个只引入 starter 的应用里，请求命中了受菜单管辖且当前用户无权限的端点
- **THEN** 响应携带权限拒绝语义与可识别的拒绝编码
- **AND** 不出现框架默认的裸错误页或 HTTP 500

#### Scenario: 零额外配置时行级判定拒绝得到统一结果

- **WHEN** 同一个应用里调用被行级操作权限拒绝的方法
- **THEN** 响应与菜单拒绝使用同一个拒绝语义出口

### Requirement: 拒绝出口唯一且可被使用方替换

系统 MUST 为同一类拒绝只提供一个生效出口；使用方自行定义同类处理时，框架的默认出口 MUST 让位，而不是与使用方的定义同时竞争同一次异常。

#### Scenario: 使用方自带拒绝处理

- **WHEN** 应用自己声明了处理权限拒绝的组件
- **THEN** 该应用的拒绝结果只由它自己的定义决定
- **AND** 不因为框架也注册了同类出口而产生两处输出

### Requirement: 扩展点缺失的启动结果与强制程度一致

系统 SHALL 区分强制扩展点与可选扩展点：强制扩展点在容器中没有实现时应用 MUST 启动失败，且失败原因能定位到缺失的那个扩展点类型；可选扩展点缺失时应用 MUST 正常启动并记录一条跳过对应功能的说明。

#### Scenario: 缺少当前用户上下文实现

- **WHEN** 应用没有提供当前用户上下文的实现就启动
- **THEN** 启动失败
- **AND** 失败信息指向缺失的那个扩展点，而不是无关的下游异常

#### Scenario: 缺少菜单权限处理实现

- **WHEN** 应用提供了用户上下文但没有提供菜单权限处理的实现就启动
- **THEN** 启动失败，且失败信息指向菜单权限处理这个扩展点

#### Scenario: 缺少菜单持久化实现

- **WHEN** 应用没有提供菜单持久化实现就启动
- **THEN** 应用启动成功
- **AND** 记录一条"菜单注册被跳过"的日志，不影响其余能力
