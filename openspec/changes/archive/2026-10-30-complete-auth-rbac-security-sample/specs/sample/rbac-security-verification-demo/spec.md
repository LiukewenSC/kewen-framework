# Spec Delta

## Purpose

约束 RBAC 与 Spring Security 登录态融合示例的验证义务：登录人是权限判定的唯一身份来源，当前用户由框架端点交付，身份与判权结果的对应关系在页面和脚本中同源可执行，且示例默认不依赖任何外部身份源。

## ADDED Requirements

### Requirement: 登录身份是示例权限判定的唯一来源

示例 MUST 使用登录后的认证主体作为 RBAC 权限装载与全部判权的唯一身份来源。示例 MUST NOT 提供会取代框架默认实现的用户来源、当前用户上下文或密码编码器，MUST NOT 通过请求头、参数或其它请求级声明改变判权身份。

#### Scenario: 请求级身份声明不改变判权结果

- **WHEN** 已以用户 A 登录的会话在受管辖请求上附带声明为用户 B 的请求头
- **THEN** 判权结果仍按用户 A 的角色与部门计算
- **AND** 响应中的当前用户仍是用户 A

#### Scenario: 同一套权限配置换登录人得到不同结果

- **WHEN** 两个角色与部门归属不同的账号分别登录并访问同一批端点
- **THEN** 各自的放行、拒绝与可见数据均按各自账号的权限计算
- **AND** 不需要修改任何权限配置或重启应用

### Requirement: 当前用户由框架端点交付

示例 MUST 以框架提供的当前用户端点（路径由既有的当前用户地址配置项指定）作为页面判定登录态与展示权限的唯一来源。示例 MUST NOT 另建同义接口供页面使用。

#### Scenario: 未登录访问当前用户端点

- **WHEN** 未认证的请求访问当前用户端点
- **THEN** 返回未登录语义的失败结果
- **AND** 登录页据此渲染账号密码表单

#### Scenario: 登录后读取当前用户

- **WHEN** 用户完成账号密码登录并读取当前用户端点
- **THEN** 返回该账号的用户名、展示信息与权限集合
- **AND** 权限集合内容与本系统账号数据一致，不包含身份源声明

### Requirement: 身份与端点的判权矩阵可执行且同源

示例 MUST 提供一张身份 × 端点的期望结果矩阵，覆盖菜单访问、数据范围、行级数据操作与部门继承四类判定。页面 MUST 能对当前登录身份逐行展示期望、实际与结论，并支持一键重跑；验证脚本 MUST 能对全部演示身份复现同一矩阵。矩阵中的用例 MUST 是只读调用或不产生可观察副作用的调用。

#### Scenario: 页面一键验证当前身份

- **WHEN** 用户在验证台点击“测试当前身份”
- **THEN** 每一行给出期望值、实际值与通过或不通过的结论
- **AND** 页面给出本次运行的汇总

#### Scenario: 脚本复现同一矩阵

- **WHEN** 应用启动后运行验证脚本
- **THEN** 脚本按文档中的同一批用例与期望值逐条输出通过或不通过
- **AND** 任一账号的任一用例不满足期望时脚本以非零状态结束

#### Scenario: 区分“拒绝”与“允许但数据为空”

- **WHEN** 某账号对数据范围端点没有可见数据但拥有该端点的访问资格
- **THEN** 该端点返回成功结果且数据集为空
- **AND** 不把这种结果与菜单拒绝或操作拒绝混为一谈

### Requirement: 默认启动不依赖任何外部身份源

示例 MUST 在默认配置下不依赖本地 IDP、外部数据库或其它外部服务即可启动，并完成账号密码登录与全部判权用例。单点登录入口 MUST 默认不配置，MUST 通过独立的可选配置按需开启；开启后单点登录身份 MUST 仍映射到本系统的同一账号，权限仍来自本系统。

#### Scenario: 没有本地 IDP 时启动

- **WHEN** 在未运行任何身份源的机器上以默认配置启动示例
- **THEN** 应用启动成功
- **AND** 登录页不出现单点登录按钮，账号密码登录与判权用例全部可用

#### Scenario: 开启单点登录后落到本地账号

- **WHEN** 以包含单点登录客户端的可选配置启动，且用户通过单点登录完成认证
- **THEN** 当前用户端点返回的是本系统对应账号的用户名
- **AND** 该会话的权限集合来自本系统账号数据

### Requirement: 示例只带业务表与幂等种子

示例 MUST NOT 复制框架级建表脚本；其 SQL MUST 只包含示例业务表结构与种子数据。种子 MUST 可重复执行，重复执行不产生重复行，且与其它示例脚本在同一数据库顺序执行时 MUST NOT 发生主键或唯一键冲突。示例 SQL MUST 进入仓库现有的 SQL 兼容性检查范围。

#### Scenario: 重复执行不翻倍

- **WHEN** 在已有种子数据的环境中再次执行示例种子
- **THEN** 各示例表的行数保持不变
- **AND** 不出现主键或唯一键冲突

#### Scenario: 与其它示例脚本共存

- **WHEN** 仓库的 SQL 兼容性检查按现有顺序执行全部示例脚本并重复一遍
- **THEN** 所有语句均被数据库接受
- **AND** 示例脚本不因其它示例已写入的账号、菜单或授权行而失败

### Requirement: 验证文档与可执行脚本使用同一批用例

示例说明文档 MUST 列出演示账号、各账号的角色与部门归属、权限来源以及身份 × 端点真值表，并 MUST 说明不在本示例范围内的能力及其归属。文档中的期望值 MUST 与页面内置真值表和验证脚本保持一致。

#### Scenario: 文档用例在脚本中都有断言

- **WHEN** 对照说明文档的真值表运行验证脚本
- **THEN** 表中的每一行都能在脚本输出中找到对应的通过或不通过结论

#### Scenario: 覆盖边界被明确标注

- **WHEN** 阅读说明文档
- **THEN** 文档指出会议室业务、单点登录联调与数据库控制台等能力不在本示例范围内
- **AND** 指明这些能力由哪个示例或哪份文档负责

#### Scenario: 种子与真值表同步

- **WHEN** 修改示例种子中的账号、角色、部门或授权行
- **THEN** 页面真值表、验证脚本与文档矩阵同步修改
- **AND** 三者对同一身份给出相同的期望结果
