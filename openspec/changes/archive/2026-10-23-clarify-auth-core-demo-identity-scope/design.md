# Design: clarify-auth-core-demo-identity-scope

## Context

验证台是单文件静态页 `sample/auth-core-boot-sample/src/main/resources/static/index.html`，无构建、无模板引擎，场景矩阵由 `S` 数组（52 条）驱动，每条自带 `demoUser / m / p / b / ck`。身份经 `X-Demo-User` 头进入 `DemoUserContextFilter`，再落入 `DemoUserContext` 的 ThreadLocal，由 `DemoAuthContextHolder` 按用户名查 `demo_user_auth`。

现状的三处不对称：

- 页面加载末尾把下拉框设为 alice 并刷新一次权限面板，但 `select` 没有 `change` 监听；
- `runAll` 与单条运行都走 `run()`，那里存在"用例未声明 `demoUser` 则回退到下拉框"的分支，而 52 条用例全部已显式声明，回退从未生效；
- README 4.1 与上述实现相反，且两处端点名仍是历史名 `/demo/current-demoUser`。

观察台三个面板中只有"当前权限"依赖身份；"各表行数"与"菜单登记"与身份无关。

## Goals / Non-Goals

**Goals:**

- 页面上身份只有一个语义：用例身份固定、手工身份显式，二者不互相继承；
- 切换手工身份后，"当前权限"回显立即可信，不残留旧快照；
- README 对验证台行为的描述与实现一致。

**Non-Goals:**

- 不引入第二个选择器或前端框架；
- 不改后端 Java、SQL、种子数据、场景断言与 `verify.sh`；
- 不改变任何权限判定与接口行为。

## Decisions

### D1 单一控件 + 明确作用域

保留下拉框，改名"手工身份"，旁边标注"仅用于权限回显与自由调用；矩阵用例各自固定身份"；把"全部运行"和汇总移入矩阵卡片，矩阵卡片标注"每条用例按自带身份执行"，行内标签补注"（固定）"。

备选：

- 在自由调用卡片内再放一个选择器 → 两个控件需要同步，状态来源翻倍，否；
- 删除下拉框、自由调用只带固定身份 → 失去手工探索不同身份的能力，否。

### D2 身份不继承（no ambient identity）

`run()` 直接使用 `s.demoUser`，删除回退分支；注释改为"每条用例必须声明 `demoUser`；`''` = 强制不带身份头"。

备选：保留回退并在界面标注"跟随"→ 未来新增用例漏写身份时会静默借用手工身份，正是本次误解的根源，否。

### D3 用 change 事件联动，不用轮询

`select.onchange` 触发一次"刷新当前权限"，并把自由调用结果重置为占位符；"各表行数""菜单登记"与身份无关，不随之刷新。初始仍保留默认 alice + 自动刷新一次，保证首屏有内容，且选择器值与被展示内容一致。

备选：定时刷新 → 无必要且制造额外请求，否；引入防抖 → 单次只读请求，过度设计，否。

### D4 自由调用结果回显身份

结果首行打印本次使用的身份（无身份时显示"无"），不再依赖用户记忆或回看选择器。

### D5 README 修正范围

只改 4.1 节两句语义描述与两处端点名；L106 的"52 条"已与 `S` 定义核对一致，不动。

## Risks / Trade-offs

- **页面无自动化测试** → 实施后用浏览器人工回归三点：切换身份权限面板更新、全部运行结果与改前一致、自由调用结果标明身份；再跑 `verify.sh` 证明服务端行为未变。
- **连续快速切换会产生多次只读请求** → 无副作用，接受。
- **删除回退后，未来用例漏写 `demoUser` 会以无身份执行** → 这是期望的显式失败，会被断言立即暴露，而不是静默借用手工身份。
