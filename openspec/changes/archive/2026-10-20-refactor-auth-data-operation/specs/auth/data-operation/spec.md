# Spec Delta

## Purpose

约束行级数据操作权限的判定范围与失败语义：一次请求涉及的每一个业务数据 ID 都必须独立命中声明的权限槽位，判定结果不得因业务主键的类型形态或调用方提供的权限内容而改变。

## ADDED Requirements

### Requirement: 每个业务数据 ID 都必须独立命中

系统 SHALL 对一次受管辖的调用所涉及的全部业务数据 ID 逐个判定权限，并 MUST 只在每一个 ID 都命中声明槽位时放行。系统 MUST NOT 只判定其中一部分 ID 而对其余 ID 沉默放行。

#### Scenario: 单个 ID 命中放行

- **WHEN** 调用受管辖的方法，其承载对象交出一个 ID，且该 ID 在声明的业务功能与操作类型下持有当前登录人拥有的权限
- **THEN** 调用被执行

#### Scenario: 单个 ID 未命中拒绝

- **WHEN** 交出的 ID 在声明槽位下不存在当前登录人拥有的权限记录
- **THEN** 调用被拒绝且方法体不执行

#### Scenario: 多个 ID 全部命中放行

- **WHEN** 一次调用涉及多个 ID，且每个 ID 都在声明槽位下命中当前登录人的权限
- **THEN** 调用被执行

#### Scenario: 多个 ID 部分命中整体拒绝

- **WHEN** 一次调用涉及多个 ID，其中至少一个 ID 未命中当前登录人的权限
- **THEN** 调用被整体拒绝
- **AND** 方法体不因已命中的 ID 而执行

#### Scenario: ID 分散在多个参数与集合元素中

- **WHEN** 一次调用的多个实参各自承载 ID，或某个数组/集合实参的元素各自承载 ID
- **THEN** 这些 ID 全部纳入判定，无一被忽略

### Requirement: 承载对象显式交出全部业务数据 ID

系统 SHALL 要求承载对象交出它所承载的业务数据 ID 的集合，并 MUST 以该集合为判定范围。单值场景以一个元素的集合表达；系统 MUST NOT 依赖取第一个元素或猜测对象内部结构来确定判定范围。

#### Scenario: 单值业务交出一条 ID

- **WHEN** 请求体只表示一条业务数据
- **THEN** 承载对象交出含一个元素的集合，判定按该元素进行

#### Scenario: 批量业务交出多条 ID

- **WHEN** 请求体本身表示多条业务数据
- **THEN** 承载对象一次交出这批 ID，全部纳入判定

#### Scenario: 实参中没有承载对象

- **WHEN** 方法被声明受管辖，但其实参中找不到任何交出业务数据 ID 的对象
- **THEN** 调用以配置类错误失败
- **AND** 不因找不到判定对象而放行

### Requirement: 待授权 ID 数量上限

系统 MUST 在单次调用涉及的 ID 总数（去重后）超过 100 时直接失败，并且 MUST NOT 通过内部分批把超限请求拆成多次判定。

#### Scenario: 达到上限正常判定

- **WHEN** 一次调用涉及去重后 100 个 ID
- **THEN** 按逐个命中的规则正常判定

#### Scenario: 超出上限直接失败

- **WHEN** 一次调用涉及去重后超过 100 个 ID
- **THEN** 调用以配置类错误失败
- **AND** 系统不发起任何权限查询

### Requirement: 判定只依据声明槽位下的权限记录，不做跨操作回退

系统 SHALL 只依据权限表中与声明的业务功能和操作类型同时匹配的记录来判定，并且 MUST NOT 在某操作类型下无记录时回退到其他操作类型的记录。

#### Scenario: 同一数据不同操作各自独立

- **WHEN** 某条数据只在操作类型 A 下配置了权限，而调用声明的是操作类型 B
- **THEN** 调用被拒绝

#### Scenario: 权限集合为空即拒绝

- **WHEN** 当前登录人不持有任何权限
- **THEN** 调用被拒绝
- **AND** 系统不因权限集合为空而放行

### Requirement: 判定不受业务主键类型影响

系统 SHALL 对数值型与字符串型业务主键提供同样的判定能力，并且 MUST NOT 因主键类型与权限表中存储形态的类型差异把已授权的调用误判为未授权。

#### Scenario: 字符串主键业务正常判定

- **WHEN** 某业务功能的数据 ID 是字符串，权限表中存有该 ID 的授权记录
- **THEN** 持有对应权限的调用被放行

#### Scenario: 同一 ID 的不同数值形态不误判

- **WHEN** 交出的 ID 与权限表读回的 ID 在数值上相同但类型形态不同（如整型与长整型）
- **THEN** 判定按归一化后的值比对，结果不因类型形态而改变

#### Scenario: 权限维护不依赖主键类型

- **WHEN** 对字符串主键的业务数据编辑或清空其数据权限
- **THEN** 维护操作正常完成，不因标识类型不受支持而失败

### Requirement: 权限数据的读写不受调用方输入内容影响

系统 MUST 把调用方提供的权限标识与权限描述作为数据而非语句内容处理，二者在写入与查询时 MUST NOT 被解释为查询语法的一部分。

#### Scenario: 含引号的权限描述原样存储

- **WHEN** 写入的权限描述中含有引号或注释符号
- **THEN** 该内容作为字符串原样存入对应记录
- **AND** 不新增、不修改、不删除任何其他记录

#### Scenario: 传入 ID 中的语句内容不扩大匹配

- **WHEN** 交出的业务数据 ID 值中包含引号或其他查询语法字符
- **THEN** 判定按整值等值比对进行
- **AND** 不会因为该值被拆成语句片段而匹配到本不属于它的授权记录

### Requirement: 权限拒绝与配置错误区分表达

系统 SHALL 区分"当前登录人无权执行该操作"与"该调用无法被判定（配置或用法错误）"两类失败，并且 MUST NOT 把框架内部类型信息作为拒绝原因输出给调用方。

#### Scenario: 权限拒绝输出统一语义

- **WHEN** 判定因权限未命中而拒绝
- **THEN** 返回统一的权限拒绝结果
- **AND** 未命中的 ID 明细只进入服务端日志

#### Scenario: 配置错误不被当作权限拒绝

- **WHEN** 判定因找不到承载对象、ID 集合为空或超出上限而无法进行
- **THEN** 以配置/用法类错误失败
- **AND** 对外信息不包含框架内部类名或接口名

### Requirement: 行级操作权限是显式声明的结果

系统 MUST 只对显式声明了行级操作权限的方法施加判定，未声明的方法按业务原样执行。

#### Scenario: 未声明即不判定

- **WHEN** 调用一个未声明行级操作权限的写接口，且该数据在权限表中存在受控记录
- **THEN** 方法按业务原样执行，不发生任何权限判定
