# Spec Delta

## Purpose

约束校验用正则常量集合的成员构成，使每个常量的实际匹配行为与其名称所承诺的语义一致，避免调用方按名称选用后得到比预期更宽松的校验。

## ADDED Requirements

### Requirement: 常量名必须与正则语义一致

每个校验常量的匹配行为 SHALL 与其名称可读出的语义相符。系统 MUST NOT 提供名称暗示某种排除或限制、而正则实际不做该限制的常量。

#### Scenario: 名称含排除语义的常量

- **WHEN** 开发者选用一个名称中含"排除某类字符"语义的校验常量
- **THEN** 该常量对应的正则确实拒绝被排除类的字符
- **AND** 不同排除组合的常量之间正则值互不相同

#### Scenario: 无法为名称提供对应实现

- **WHEN** 某个名称暗示的语义没有可靠对应的正则实现
- **THEN** 该常量不出现在公开集合中，而不是以宽松实现占位

### Requirement: 公开常量集合不含同值别名

同一公开常量集合中 MUST NOT 存在两个名称不同但正则逐字节相同、且语义上应有所区别的常量成员。

#### Scenario: 检查集合成员

- **WHEN** 枚举公开的正则常量集合
- **THEN** 不存在仅靠名称区分、正则值却完全相同的成组成员
- **AND** 确属同一语义的别名（如浮点数的两种历史叫法）通过引用同一定义表达，而非重复字面量

### Requirement: 字符类正则不含意外字面量

中文、手机号等字符类校验常量的正则 SHALL NOT 在字符类中或量词前包含无意的字面字符，使匹配结果超出该常量声明的字符范围。

#### Scenario: 校验纯中文

- **WHEN** 用中文校验常量匹配"你好"
- **THEN** 匹配成功
- **AND** 用同一常量匹配"你好,,,"时匹配失败

#### Scenario: 校验手机号

- **WHEN** 用手机号校验常量匹配含逗号的 11 位串
- **THEN** 匹配失败
- **AND** 匹配当前在用的各号段 11 位号码时匹配成功
