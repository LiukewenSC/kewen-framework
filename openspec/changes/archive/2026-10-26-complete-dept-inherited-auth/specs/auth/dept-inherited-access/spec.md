# Spec Delta

## Purpose

约束部门级权限沿部门层级向下继承的行为：继承的边界到哪里、继承关系在什么时机展开、权限串如何编解码，以及这条通路在权限体缺失或部门层级畸形时的对外结果。

## ADDED Requirements

### Requirement: 部门继承权限只授予子孙部门

以"部门继承"标记授予某部门的权限，SHALL 只对该部门**严格子孙部门**的成员生效。该部门自己的成员 MUST NOT 因这条授权获得权限；本部门成员要靠部门标记本身授权。判定依据是权限字符串是否完全一致，不区分层级深度。

#### Scenario: 本部门成员不命中继承授权

- **WHEN** 某端点被授权给部门 B 的继承标记，请求者是部门 B 自己的成员，且不属于 B 的任何子部门
- **THEN** 请求者对该端点没有权限
- **AND** 不因"权限配在自己头上"而放行

#### Scenario: 直接子部门成员命中

- **WHEN** 部门 C 是 B 的直接子部门，某端点被授权给部门 B 的继承标记，请求者是部门 C 的成员
- **THEN** 请求者对该端点有权限

#### Scenario: 隔级子孙同样命中

- **WHEN** 部门 D 是 B 的孙部门（中间隔了一层），某端点被授权给部门 B 的继承标记，请求者是部门 D 的成员
- **THEN** 请求者对该端点有权限
- **AND** 结果与"请求者是直接子部门成员"一致，继承不设层数上限

#### Scenario: 根部门成员没有可继承的上级

- **WHEN** 请求者只隶属于父级为根的部门，且该部门自身没有被直接授权
- **THEN** 请求者不因为根的继承标记而获得任何权限

#### Scenario: 多部门任职取并集

- **WHEN** 请求者同时隶属于部门 B 和部门 C，而 C 是 B 的子部门，某端点被授权给部门 B 的继承标记
- **THEN** 请求者对该端点有权限（经由 C 的上级链命中）
- **AND** 其作为 B 成员的身份不产生该权限，也不抵消它

### Requirement: 继承关系在装载时展开而非存储时展开

用户的部门继承权限 SHALL 在每次装载用户权限时按当时的部门层级现算。系统 MUST NOT 把展开出的继承权限写入用户的授权数据，因此部门层级调整后，下一次装载即生效，不需要重刷任何用户的授权记录。

#### Scenario: 调整部门层级后无需重刷用户授权

- **WHEN** 把一个已有成员的部门挂到另一个部门之下，随后重新装载这些成员的权限
- **THEN** 他们立即获得新上级所授予的继承权限
- **AND** 用户的授权数据没有被写入或改写

#### Scenario: 展开结果不落入用户授权存储

- **WHEN** 检查用户授权相关的数据表内容
- **THEN** 其中不出现按部门层级展开出来的继承权限串

### Requirement: 部门继承权限的编解码无损往返

授予给某个部门的继承权限串 SHALL 能被解析回配置权限对象，再序列化回完全相同的权限串与描述。往返 MUST NOT 依赖任何不随权限串存储的字段（如层级深度），因此解析回来的对象在权限判定上与授权时等价。

#### Scenario: 入库串解析回对象再序列化一致

- **WHEN** 一条继承权限串被解析为配置权限对象，随后由该对象重新序列化
- **THEN** 得到的权限串与描述与入库值完全一致

#### Scenario: 不随权限串存储的深度字段不影响判定

- **WHEN** 同一条继承权限串分别由"带层级深度信息"和"层级深度信息已丢失"的两个对象序列化
- **THEN** 两者产出的权限串相同

### Requirement: 权限标记必须是单段令牌

每个权限实体的标记 SHALL 不含次级分隔符，使一条权限的"位置数"与标记自身拆出的段数一致。MUST NOT 出现标记被误当成多个位置参与拼接的权限串。

#### Scenario: 继承型标记的权限串只含一个 ID 段

- **WHEN** 一个继承型权限实体被序列化为权限串
- **THEN** 该串的 ID 部分只有一个值，描述部分也只有一个值
- **AND** 把它解析回实体不报错，且 ID 与名称正确

#### Scenario: 标记含次级分隔符视为非法

- **WHEN** 新增的权限实体把含次级分隔符的字符串用作标记
- **THEN** 该实体的权限串往返产生与原始授权不一致的结果，属于必须修掉的缺陷，不得入库

### Requirement: 权限体缺失时认证装载不得失败

当用户没有凭证，或权限体未能装载出该用户本身时，装载用户认证信息 SHALL 仍然成功返回，其权限集合为空。系统 MUST NOT 因此抛出未处理异常而使登录或取当前用户失败。

#### Scenario: 无凭证用户被装载

- **WHEN** 一个存在但没有凭证记录的用户被装载为认证主体
- **THEN** 装载成功返回该用户的认证信息
- **AND** 其权限集合为空，而不是抛出异常

#### Scenario: 权限体未装载出用户本身

- **WHEN** 用户权限体存在但其用户部分缺失
- **THEN** 汇总该权限体得到空权限集合，不抛出未处理异常
- **AND** 该请求者对所有受管辖端点都无权限

### Requirement: 畸形部门层级不得造成无限查询

按部门展开上级链时，系统 SHALL 对自引用与成环的层级数据给出确定的终止结果。MUST NOT 因脏数据陷入无限循环或无限查库。

#### Scenario: 部门的父级指向自己

- **WHEN** 某部门的父级 ID 等于它自己的 ID，装载隶属于它的用户权限
- **THEN** 装载正常完成，父链不含无意义的重复
- **AND** 不发生超出层数上限的重复查询

#### Scenario: 两个部门互为父级

- **WHEN** 部门 A 的父级是 B、部门 B 的父级是 A，装载隶属于 A 的用户权限
- **THEN** 装载正常完成并给出确定的权限集合
- **AND** 不出现无限循环

### Requirement: 部门继承语义必须有端到端验证载体

基于权限模型层的示例 SHALL 提供可指认的端到端用例来承载"只授予子孙部门"这条语义，其中必须包含"权限配在部门 B 上，B 的成员与 B 的子部门成员访问同一端点结果不同"的对照。用例 MUST 以真实请求的允许/拒绝结果作判据，MUST NOT 用对内部方法的直接调用替代。

#### Scenario: 同一端点三种身份对照

- **WHEN** 一个端点被授权给部门 B 的继承标记，分别以 B 的成员、B 的子部门成员、与 B 无层级关系的部门成员身份请求同一端点
- **THEN** 只有 B 的子部门成员获得放行
- **AND** 另外两者得到拒绝

#### Scenario: 示例的部门数据构成真实层级

- **WHEN** 检查示例的部门种子数据
- **THEN** 其中至少存在一条父子关系明确的部门链，且父、子、无关系三个位置各有成员可被用作对照身份
