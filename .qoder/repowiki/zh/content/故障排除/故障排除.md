## 简介
本指南面向使用 Kewen Framework 的开发者与运维人员，聚焦以下典型问题：
- 权限不生效、越权访问
- 单点登录连接失败、令牌验证错误
- 权限查询缓慢、内存占用过高
- 全局异常返回不一致、Spring Security 错误页重定向
- SQL 脚本在不同数据库或重复执行时的兼容性问题

文档按“现象—原因—定位步骤—解决方案”的结构组织，并提供代码级引用和可视化流程图，帮助快速定位根因。

## 项目结构与排查范围
Kewen Framework 在权限与认证方面主要由以下模块构成：
- `auth`：权限核心模型、RBAC 实现及 Spring Boot Starter 装配。
- `login-spring-boot-starter`：安全登录、OAuth2/OIDC/SAML2 接入、统一异常处理、过滤器链。
- `basic`：基础异常体系、参数校验异常处理、通用响应结构。
- `basic-support`：请求日志持久化、方糖消息通知等支撑能力。
- `boot`：租户、存储、Magic 等启动器。
- `scripts`：SQL 兼容性检查工具。

## 权限配置问题排查
### 权限不生效
可能原因：
- 引入 Starter 不完整，缺少 `login-spring-boot-starter` 或 `auth-rbac-spring-boot-starter`。
- 权限数据表名、列名与 `cu.auth.auth-data-table.*` 配置不一致。
- 菜单与权限数据未入库或缓存未刷新。
- RBAC 相关 Bean 未正确装配。

排查步骤：
1. 确认依赖已引入 `login-spring-boot-starter` 与 `auth-rbac-spring-boot-starter`。
2. 检查 `cu.auth.auth-data-table.table-name`、`business-function-column`、`data-id-column`、`operate-column`、`authority-column`、`description-column` 是否与数据库一致。
3. 如启用 `cu.auth.cache-auth=true`，修改权限后需重启或清理缓存；否则每次直接查库。
4. 通过示例工程或单元测试思路验证 RBAC 自动装配是否生效。

### 越权访问
可能原因：
- 接口未添加菜单权限注解或数据操作注解。
- 数据范围注解未正确使用，导致查询列表过滤失效。
- 权限拒绝出口未按预期装配，退化为 HTTP 500。

排查步骤：
1. 确认业务接口是否正确声明菜单权限和数据权限注解。
2. 检查 RBAC 中角色、用户、部门与权限的关联关系。
3. 观察返回结果是否为统一的 JSON 失败响应；若非，检查 `AuthExceptionHandler` 装配逻辑。
4. 若测试发现拒绝通道缺失，说明 Starter 装配或扫描路径存在问题。

## 认证失败问题排查
### SSO 连接失败
常见表现：
- 浏览器跳转 IdP 后回调失败。
- 控制台出现 SSL、端点不可达、授权码无效等错误。
- 成功回调但未创建会话。

排查要点：
1. 确认 `cu.security.login.oauth2.sso-authorization-uri`、`login-processing-url`、客户端列表配置完整。
2. 检查 IdP 分配的 `client-id`、`client-secret`、回调地址模板是否与应用侧一致。
3. OIDC 模式下确认 `issuer-uri`、`user-info-uri`、`jwk-set-uri` 可访问且证书有效；必要时开启 `ignore-ssl`（仅测试环境）。
4. 若使用 SAML，检查 metadata 资源路径、SP Entity ID、ACS 回调地址。

### 令牌验证错误
可能原因：
- `user-name-attribute-name` 配置的值与 IdP 实际字段不一致。
- OIDC 的 JWK Set 不可用或密钥过期。
- 回调地址与 IdP 侧登记不一致。
- 网络代理或证书链导致 TLS 握手失败。

排查步骤：
1. 打开 OAuth2/OIDC 日志，观察 token 请求和用户信息请求是否成功。
2. 核对 `user-name-attribute-name` 是否指向本系统用户名，而非 IdP 的 `sub`。
3. 若启用 OIDC，确认 `.well-known/openid-configuration` 和 JWK Set 可达。
4. 检查 `ignore-ssl=false` 时证书链是否完整；测试环境可临时设为 true 以缩小问题范围。

### 本地用户未找到
框架在身份源认证成功但本地不存在对应账号时，会给出明确的单点登录失败原因码。

诊断要点：
- 关注异常中的 error code，例如 `sso_local_user_not_found`。
- 确认 IdP 返回的用户名字段与本地系统用户名一致。
- 检查 `SecurityUserDetailsService` 或对应的本地用户加载逻辑是否能根据该用户名查到用户。

## 性能问题排查
### 权限查询缓慢
可能原因：
- 权限数据未缓存，每次请求都查库。
- 权限表缺少必要索引。
- 权限范围过大，导致单次查询数据量过高。

优化建议：
- 在稳定环境下开启 `cu.auth.cache-auth=true`，减少频繁查库。
- 为权限相关表建立合理索引，尤其按业务功能、数据 ID、操作类型查询的列。
- 结合业务场景限制数据范围，避免一次性拉取超大权限集合。

**章节来源**
- [docs/application.yml:1-211](file://docs/application.yml#L1-L211)

### 内存占用过高
可能原因：
- 会话中保存了大量身份信息、原始声明或 ID Token。
- 请求日志持久化开启但写入量大。
- 权限对象或上下文持有过大的静态缓存。

优化建议：
- 评估是否需要将请求日志持久化到数据库；若不需要，关闭 `cu.request.persistent.database`。
- 控制会话并发数和会话生命周期，避免过多长会话。
- 避免在上下文中保存不必要的敏感大对象；对大型权限集合做分页或按需加载。

## 调试技巧与工具
### 日志级别调整
- 观察业务异常时，检查 `GlobalExceptionHandlerAdvice` 记录的业务异常日志。
- 观察安全相关异常时，检查 `AuthenticationExceptionAdviceHandler` 记录的安全异常日志。
- 若出现 `/error` 重定向或 Tomcat 默认错误页，检查 `WebSecurityGlobalExceptionHandlerFilter` 是否捕获了 Spring Security 过滤器链中的异常。

建议：
- 开发环境提高关键包日志级别，便于跟踪认证、权限、异常处理链路。
- 生产环境保持 INFO 及以上，仅在复现问题时短期提升。

## 错误码与异常信息对照
### 基础异常体系
- `BackendException`：基础运行时异常，默认错误码 500。
- `BizException`：业务异常，继承 `BackendException`。
- `ExceptionConstant.BIZ_FAILED`：业务失败错误码常量。

- `BizException`
- `NullPointerException`
- 参数校验异常 `MethodArgumentNotValidException`

### 安全认证异常
`AuthenticationExceptionAdviceHandler` 负责将安全异常转换为统一 JSON：
- `AccessDeniedException`：返回 401。
- `NoLoginException`：返回 401。
- `AuthenticationException`：返回 403。
- `InternalAuthenticationServiceException`：返回 500。
- `InsufficientAuthenticationException`：返回 401，提示需要重新登录。
- 兜底 `Throwable`：返回 500。

### 常见问题与修复建议
- 注释或字符串中包含分号导致语句拆分错误：工具已处理引号和注释，但仍应避免复杂嵌套。
- 非幂等的 `INSERT`：改为 `INSERT IGNORE`、`MERGE` 或先判断是否存在。
- 数据库关键字冲突：使用反引号或双引号包裹标识符。
- 字符集与排序规则不一致：确保 DDL 指定统一字符集。
- H2 MySQL 模式接受的语法与 MySQL 不完全一致：脚本通过后仍需在实际 MySQL 环境验证。

## 系统监控与告警建议
### 监控指标
- 认证成功率与失败率：按协议维度统计 OAuth2/OIDC/SAML 成功与失败次数。
- 本地用户匹配失败率：重点监控 `sso_local_user_not_found`。
- 权限拒绝率：统计 401、403 返回比例。
- 数据库慢查询：权限相关 SQL 的执行时间、扫描行数。
- 会话数量与大小：监控会话表增长趋势。
- 请求日志写入量：若开启 `cu.request.persistent.database`，监控写入延迟与表增长。

### 告警策略
- 认证失败率突增：触发告警并通知安全团队。
- 本地用户未找到比例升高：检查 IdP 用户名映射和本地用户数据。
- 权限拒绝率突然下降：可能表示权限校验失效，存在越权风险。
- 数据库慢查询增多：优化权限表索引或关闭非必要缓存。
- 会话表增长过快：检查会话生命周期和并发登录策略。

### 日志采集
- 集中采集应用日志，重点关注 `AuthenticationExceptionAdviceHandler`、`GlobalExceptionHandlerAdvice`、`WebSecurityGlobalExceptionHandlerFilter` 的输出。
- 将认证失败、权限拒绝、参数校验失败作为关键事件埋点。
- 对敏感信息脱敏后再落盘，避免泄露密码、token、会话内容。

## 结论
Kewen Framework 在权限与认证方面提供了注解驱动、RBAC 默认实现、统一异常处理和 SSO 接入能力。排查问题时，应优先从“配置—异常—日志—数据库—外部依赖”五个维度逐步收敛；遇到权限拒绝语义不一致时，关注 Starter 装配和全局异常处理器；遇到 SSO 失败时，优先核对 IdP 端点和用户名映射；遇到 SQL 问题时使用内置兼容性工具提前发现隐患。配合合理的监控与告警，可在问题扩大前及时发现并处理。
