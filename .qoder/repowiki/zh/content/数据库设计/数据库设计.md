## 引言
本文件面向 Kewen Framework 的数据库设计，聚焦权限体系、系统配置和审计日志三类数据。文档基于仓库中的 SQL 初始化脚本及对应的 MyBatis-Plus 实体类，说明用户、角色、部门、菜单、路由、凭证、应用行级权限槽位、文件记录、请求日志等表的结构、业务含义、约束、索引、视图以及示例模块自定义表的用途。同时给出完整的 ER 图、建表范围、迁移策略和维护建议，帮助读者在理解框架约定后，安全扩展自己的业务表和权限槽位。

## 核心数据模型
Kewen Framework 的数据库模型可以划分为四类：
- 身份与组织：用户、角色、部门、用户凭证、用户部门关联、用户角色关联
- 权限与菜单：应用行级权限槽位、菜单 API、菜单路由、菜单权限关联
- 基础支撑：文件详情、文件分片、存储任务、请求日志
- 示例业务：示例模块为演示行级数据权限和业务场景而定义的额外表

### 身份与组织表族
| 表名 | 主键 | 关键字段 | 业务含义 | 关键约束 |
|---|---:|---|---|---|
| `sys_user` | `id` | `username`、`phone`、`email`、`gender`、头像 ID | 系统用户基本信息 | `username`、`phone` 唯一；默认时间戳 |
| `sys_user_credential` | `id` | `user_id`、`password`、过期时间、锁定截止时间、启用标志 | 用户登录凭证与安全控制 | `user_id` 唯一；支持免密登录扩展 |
| `sys_role` | `id` | `name` | 角色名称 | 默认时间戳 |
| `sys_dept` | `id` | `name`、`parent_id` | 部门树，`parent_id=0` 表示根部门 | 自引用层级 |
| `sys_user_dept` | `id` | `user_id`、`dept_id`、`is_primary` | 用户多部门归属，标记主要部门 | 复合索引 `(user_id, dept_id)` |
| `sys_user_role` | `id` | `user_id`、`role_id` | 用户与角色的多对多关系 | 复合索引 `(user_id, role_id)` |

### 权限与菜单表族

### 示例模块自定义表族
示例模块为演示行级数据权限、菜单授权、多表别名、批量上限等业务能力，定义了以下表：

- `demo_user_auth`：示例用户权限表，作为当前用户上下文的数据源

- `demo_execution_log`：副作用证据表，证明受管辖写方法是否真正执行

## 依赖与关系分析
- 用户到凭证：一对一，凭证表通过 `user_id` 唯一键保证一个用户一条凭证
- 用户到角色：多对多，通过 `sys_user_role` 解耦
- 用户到部门：多对多，通过 `sys_user_dept` 解耦，并支持主要部门标记
- 部门到部门：自引用树形结构，根部门 `parent_id=0`
- 菜单 API 到菜单权限：一对多，`sys_auth_menu.api_id` 指向 `sys_menu_api.id`
- 菜单 API 到菜单路由：一对多，`sys_menu_route.api_id` 指向 `sys_menu_api.id`
- 菜单 API 到行级权限：间接关联，通过 `business_function`、`operate`、`data_id`、`authority` 组合判定
- 请求日志到用户：逻辑关联，通过 `user_id` 与 `sys_user.id` 对应

## 性能与索引设计
现有脚本已针对高频查询建立必要索引：
- `sys_auth_data`：`(business_function, operate, data_id, authority)` 复合索引，优化行级权限匹配
- `sys_menu_api.path`：唯一索引，避免路径冲突并加速菜单查询
- `sys_user.username`、`sys_user.phone`：唯一索引，保证用户标识唯一
- `sys_user_role(user_id, role_id)`：优化用户角色查询
- `sys_user_dept(user_id, dept_id)`：优化用户部门查询
- `sys_user_credential.user_id`：唯一索引，保证凭证一对一

建议补充：
- `sys_request_log` 按 `create_time`、`trace_id`、`api_path` 建立查询索引，提升审计检索效率
- `file_detail.url`、`file_detail.object_id`、`file_detail.platform` 视使用情况建立索引
- `sys_menu_route.deleted`、`sys_menu_route.type` 若频繁过滤，可考虑复合索引
- 大表建议分区或归档，尤其是 `sys_request_log`、`file_detail`

## 迁移与版本管理
仓库采用“脚本即事实”的方式管理数据库结构：
- 框架通用脚本位于 `docs/sql`，不写引擎、字符集、排序规则，交由目标库默认值
- 兼容性通过 `scripts/check-sql-compat.sh` 用 H2 实测校验
- 示例模块脚本使用 `CREATE TABLE IF NOT EXISTS`，避免重复建表；种子数据使用幂等插入守卫
- 示例 RBAC 模块的种子数据注释明确区分 H2 profile 自动执行与 MySQL 手动导入

迁移建议：
- 新增表时遵循 `docs/sql` 风格：兼容 MySQL 与 H2(MODE=MySQL)，不写存储引擎和字符集
- 增量变更优先使用 `ALTER TABLE`，并在变更脚本中标注版本和回滚方案
- 保持实体类、SQL 脚本、业务注释三者一致，避免 MyBatis-Plus 字段映射错乱
- 对大表变更谨慎进行在线 DDL，必要时分批迁移

## 初始化与维护指南

### 初始化步骤
1. 先执行框架通用脚本：`docs/sql/auth-rbac.sql`、`docs/sql/basic-support.sql`
2. 再执行示例模块自有表脚本：`sample/auth-core-boot-sample/sql/schema.sql`、`sample/auth-rbac-boot-sample/sql/schema.sql`
3. 根据需要执行种子数据：

   - 示例 rbac：`sample/auth-rbac-boot-sample/sql/seed-data.sql`（注意其注释说明 MySQL 侧需手动导入）

### 常见维护操作
- 用户与凭证：
  - 修改密码时应同步更新 `password` 与 `password_expired_time`
  - 锁定账号时设置 `account_locked_deadline`；解除锁定时清空或设为早于当前时间
  - 禁用账号时将 `enabled` 置为 0
- 角色与部门：
  - 调整部门层级时注意 `parent_id` 一致性，避免环路
  - 为用户分配多个部门时，仅将一个设为主要部门
- 菜单与权限：
  - 新增 API 后登记 `sys_menu_api`，并根据需要登记 `sys_auth_menu`
  - 行级权限通过 `sys_auth_data` 授予具体业务数据，确保 `business_function`、`operate`、`data_id`、`authority` 组合正确
- 文件与存储：
  - 手动分片上传完成后，核对 `file_part_detail` 与 `sys_storage_file.status`
  - 清理无效缩略图和冗余元数据，释放存储空间
- 审计日志：
  - 按 `create_time` 归档历史日志
  - 对敏感 `body`、`params` 做脱敏处理
  - 使用 `trace_id` 关联一次请求的多条日志

- 使用 `WHERE NOT EXISTS` 防止重复插入

- 示例菜单授权与权限槽位数据配合，便于验证行级判定是否正确生效

## 结论
Kewen Framework 的数据库设计以 RBAC 为核心，围绕用户、角色、部门、菜单、路由和行级数据权限构建灵活的安全模型；同时提供文件存储和请求日志等基础支撑表。现有脚本注重跨数据库兼容性，并通过示例模块展示行级权限、菜单授权、部门继承、多表别名等典型用法。实际项目中，应在保持框架约定前提下，扩展业务表和权限槽位，完善索引、归档和迁移策略，使权限控制、可观测性与可维护性达到一致水平。
