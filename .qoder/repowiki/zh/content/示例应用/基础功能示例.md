## 简介
本文件围绕 `basic-boot-sample` 基础功能示例，系统说明它如何演示 Kewen Framework 的基础支撑能力：全局异常处理、统一响应信封、请求参数校验、Jackson 日期序列化、过滤器链执行顺序、日志记录（请求日志与追踪）、异步方法、以及 Spring Boot 启动生命周期扩展。该示例不直接实现业务逻辑，而是通过轻量控制器和测试用例，验证框架层在 Web 请求进入、处理、返回全链路中的通用行为。

## 详细组件分析

### 全局异常处理与统一响应
示例没有自定义业务异常类型，但通过测试断言了框架层的统一响应契约：

- 成功响应包含 `code`、`success`、`message`、`data`、`traceId`。
- 校验失败、JSON 反序列化失败等异常会被全局异常处理器捕获，并以失败信封返回。
- 当请求头未携带 `traceId` 时，响应中仍会生成非空追踪值；若请求头携带 `traceId`，则原样回显。

```mermaid
flowchart TD
    Start(["进入全局异常处理"]) --> CheckType{"异常类型判断"}
    CheckType -->|参数校验异常| BuildValidationMessage["组装字段级错误消息"]
    CheckType -->|JSON 解析异常| BuildParseError["封装解析失败信息"]
    CheckType -->|其他运行时异常| BuildGeneralError["封装通用错误信息"]
    BuildValidationMessage --> WrapEnvelope["写入统一失败信封"]
    BuildParseError --> WrapEnvelope
    BuildGeneralError --> WrapEnvelope
    WrapEnvelope --> End(["返回 HTTP 状态码与统一 JSON"])
```

### Jackson 日期序列化与反序列化
`JacksonSerializerController` 覆盖了三种典型场景：

1. `@RequestParam` 形式的 `LocalDate`、`LocalDateTime` 参数绑定。
2. 对象属性绑定方式的日期字段绑定。
3. `@RequestBody` JSON 中的日期字段反序列化。
4. 返回 `Date`、`LocalDateTime`、`LocalDate` 观察序列化输出。

```mermaid

    BindSuccess --> Serialize["序列化为格式化字符串"]
```

#### 契约要点
- 合法的 `yyyy-MM-dd` 与 `yyyy-MM-dd HH:mm:ss` 应被接受。
- 非法日期应返回统一失败信封，而不是 Spring 默认错误页。
- 输出时 `Date`、`LocalDate`、`LocalDateTime` 应为格式化字符串，而非时间戳数字。
- 可选参数缺失时应返回 null 字段，而不是缺少键。

### 日志记录与追踪
示例通过配置项启用两类日志能力：

- 通知通道：`cu.notify.fang-tang.enabled=true`，配合 `cu.request.message.fang-tang=true`。

在测试环境中，基类通过 `@TestPropertySource` 关闭通知与消息发送，确保测试不会向外网发送请求。


## 故障排查指南
| 现象 | 可能原因 | 排查建议 |
|---|---|---|
| 校验失败后返回 HTTP 500 但业务期望 200 | 全局异常处理器将校验失败封装为统一失败信封 | 检查测试断言是否误判 HTTP 状态码；实际契约为 `success=false`、`code=500` |
| 日期参数报错或输出为时间戳 | 全局日期转换器未生效或格式不匹配 | 检查参数是否为 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`，并确认序列化输出为字符串 |
| 测试产生外部网络请求 | 通知客户端未被正确关闭 | 检查 `@TestPropertySource` 是否设置 `cu.notify.fang-tang.enabled=false` |
| 响应缺少 `traceId` | 过滤器未生效或请求头未透传 | 检查 `/filter/hello` 测试是否断言 `traceId` 非空或回显 |
| 单字段校验消息截断 | 已知缺陷：消息拼接截取逻辑存在问题 | 参考 `ValidatedTestControllerTest` 中注释说明，等待框架修复后更新断言 |

## 结论
`basic-boot-sample` 是一个高度聚焦于框架基础能力的示例工程。它不追求复杂业务，而是通过少量控制器和一组契约测试，证明 Kewen Framework 在异常处理、参数校验、Jackson 序列化、过滤器链、日志与追踪、异步执行、启动生命周期扩展等方面的可用性与一致性。对于使用者而言，它既是接入样板，也是行为基准：当框架升级时，这些测试能优先暴露破坏性变更；当业务接入时，可直接参考其中的控制器、请求模型与测试写法，复用统一响应、校验与日志模式。
